# docs/requests/ — Cowork からの依頼を置く場所

Cowork（要件整理担当）がここに Markdown を1件1ファイルで書く。
書き込みは `scripts/cowork-daemon.sh` が検知して、Claude Code をヘッドレスで起動する。
**このREADME自体は監視対象から外してある**（`cowork-watch.sh` が除外）。

## 1ファイルの書き方

ファイル名は内容が分かるものにする（例：`予定の色分けを増やす.md`、`gmail-search.md`）。
中身はこの3点が読み取れれば着手される。決まった書式は要らない。

```markdown
# 予定に「繰り返し」の終了日をつけたい

## 何を変えたいか
毎週の予定を作ったとき、いまは無限に続いてしまう。
「いつまで繰り返すか」を指定できるようにしたい。

## どの画面／どのデータか
予定（/schedule）の追加・編集フォーム。CalendarEvent の repeat まわり。

## 既存データをどう扱うか
すでに入っている繰り返し予定は、終了日なし（＝今まで通り無限）のままでいい。
```

## 書かなくていいもの

文言・色・並び順・細かいUIの詰めは、書かなければこちらで妥当な案を採って進める。
決めたことは実装後の報告で「こちらで決めた」と明示される。

## 止まる場合

次に当たるものは、実装せずに `.cowork/waiting.txt` に理由を書いて止まる。

- 何をしたいのかが読み取れない
- Supabase のスキーマ変更（`supabase/sql/`）が要る — SQLは人が本番で実行する必要があるため
- 本番データを消す／作り直す性質の変更
- Dexie の主キー変更など、`src/db/schema.ts` のバージョンチェーンを壊しうる移行

## いまの状況を見る

```
bash scripts/cowork-watch.sh
```
