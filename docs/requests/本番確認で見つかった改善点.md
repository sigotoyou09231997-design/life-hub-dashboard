# 本番確認で見つかった改善点

## 何を変えたいか

Chrome拡張で本番(https://life-hub-dashboard.netlify.app)を実際に操作して、直近ショップされた機能群を確認しました。ほとんど問題なく動いていましたが、以下3点は直した方がいい・改善した方がいいと感じたので報告します。

### 1. 為替換算の自動レート取得が失敗する（要調査）

旅行の費用に外貨(USD)を選んで金額を入れたところ、自動レート取得が失敗し「レートを取れませんでした。手で入れてください。」という手入力フォールバックになりました。

ネットワークログを見ると `https://api.frankfurter.app/latest?from=EUR&to=JPY` が **503** を返していました（EURで試した時のログ。USDでも同様に失敗）。手入力フォールバック自体は設計通り動いていて実害はないですが、以下を確認・検討してほしいです。

- これがFrankfurter.app側の一時的な障害なのか、呼び出し方(パラメータ・頻度・User-Agent等)に問題があって継続的に失敗しているのか
- 1回失敗したら即フォールバックではなく、1〜2回リトライしてから諦める形にできないか
- 可能なら、Frankfurter.appがダウンしている時のための予備の為替APIを1つ用意できないか（必須ではない）

### 2. 削除確認がブラウザ標準のconfirm()になっている

お金管理→給与タブで、登録済みの給与エントリのゴミ箱アイコンを押したところ、ブラウザ標準の確認ダイアログ(window.confirm)が出ました。このアプリの他の操作は全部アプリ内のモーダルで統一されているので、削除確認だけネイティブのconfirm()なのは見た目・体験として浮いています。

- 他の確認系（今後増えるかもしれない削除・破壊的操作全般）と合わせて、アプリ内のモーダルやトースト+アンドゥ方式に統一してほしいです
- 実害として、ブラウザの自動操作ツール（Claude in Chromeなど）からはネイティブconfirm()が出ると後続の操作が固まってしまう問題があり、動作確認がしづらいという副作用もありました

### 3. (任意・低優先) 給与を1件も登録していない時のサマリー画面

お金管理→サマリーは、給与を1件も登録していない状態だと「給与を登録する」ボタンだけの空表示になり、財布の現金カードなど他のウィジェットが一切見えません。給与を1件登録すると（対象月が未来でも）フルのダッシュボードが表示され、財布の現金カードも出るようになることは確認しました。

財布の現金は概念的に給与登録と独立しているはずなので、給与が0件の状態でも財布の現金カードだけは出しておく、という選択肢もあるかもしれません。優先度は低いので、余裕があれば検討してください。

## どの画面／どのデータか

1. 旅行詳細→費用タブ→費用を追加モーダルの通貨・レート欄（`src/pages/TripDetailPage.tsx` 関連、為替換算まわり）
2. お金管理→給与タブの給与エントリ削除ボタン（`src/pages/records/ExpensePage.tsx` またはその配下の給与関連コンポーネント）
3. お金管理→サマリーの空状態分岐（`src/components/expense/ExpenseSummary.tsx` の `!data` 早期リターン部分）

## 既存データをどう扱うか

データ構造の変更は不要な想定です。挙動の改善のみで、既存データへの影響はないはずです。

なお、動作確認のためにテストの給与データ（対象月2026年9月、手取り¥300,000）を1件登録しました。削除しようとした際に上記2番の確認ダイアログの問題で操作が固まってしまったため、本人が消せているか確認できていません。念のため、お金管理→給与タブに2026年9月・¥300,000というテストエントリが残っていないか確認し、残っていたら削除してください（実データではないので消して問題ありません）。
