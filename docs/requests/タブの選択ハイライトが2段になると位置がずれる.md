# タブの選択ハイライト(白背景)が、2段になるページでずれる

## 何を変えたいか

本人の指摘: 「ボタンのデザインがおかしいところがある」（送ってもらった画面は
お金管理のサマリー、白い丸背景が「サマリー」の文字と離れた左上に浮いていた）。

実際にブラウザで開いて確認したところ、原因はボタンではなくタブ切り替え
(`src/components/ui/Tabs.tsx`)の選択ハイライト(`spatial-tabs__indicator`)だった。
タブが6個あるページで、ハイライトの白い背景が選んでいるタブの文字を追わず、
コンテナ左上に小さく浮いてしまう。

再現した2画面のスクリーンショット:
- `docs/requests/screenshots/バグ_お金管理タブのハイライトがずれる.png`
  （お金管理 → サマリー/給与/固定費/履歴/カード/PayPayの6タブ）
- `docs/requests/screenshots/バグ_旅行詳細タブのハイライトがずれる.png`
  （旅行計画の旅行詳細 → 日程/費用/持ち物/ルート/日記/書類の6タブ）

### 原因（コードを読んで特定したもの）

`Tabs.tsx`の`COLS_CLASS`は2〜5列分の`grid-cols-*`しか定義していない。
タブが6個だと`COLS_CLASS[6]`が無いため、`grid-cols-3`にフォールバックして
3列×2段で並ぶ。ところがハイライトの位置・幅の計算式は1段前提のまま:

```ts
style={{ width: `calc((100% - 0.5rem) / ${options.length})`, left: "0.25rem", transform: `translateX(${activeIndex * 100}%)` }}
```

ここの`options.length`（=6）は実際の列数（3）と食い違っているため、幅は
本来の半分（1/6）で計算され、かつ横方向の移動量(`translateX`)も列の折り返しを
考慮していない。結果、ハイライトは細く縮み、2段目に選択が移っても段をまたいで
正しい位置に動かない。

タブが5個以下（1段に収まる）画面ではこの計算で問題ないため、他の画面
（予定・タスクの4タブ、メモ・リストの2タブ、ふりかえりの2タブなど）は影響ない。
6タブになっているのはこの2画面だけ確認した(`grep -rn "<Tabs" src/pages src/components`
で全箇所を洗い出し済み)。

## どの画面／どのデータか

- `src/components/ui/Tabs.tsx`（ハイライトの位置・幅の計算、および`COLS_CLASS`）
- 影響している画面: `src/pages/records/ExpensePage.tsx`（お金管理、6タブ）、
  `src/pages/TripDetailPage.tsx`（旅行詳細、6タブ）

直し方はそちらの判断でよいが、案としては次のどちらか:
1. 6タブ用に`COLS_CLASS`と、ハイライトの位置計算を「列数」と「行番号」の両方から
   出す形に直す（`activeIndex % 列数`で列位置、`Math.floor(activeIndex / 列数)`で行位置）
2. 計算式に頼らず、選択中のタブ要素そのものの位置・幅をref(`getBoundingClientRect`など)
   で測ってハイライトに反映する形に作り替える（タブの数や折り返しが増えても崩れなくなる）

## 既存データをどう扱うか

見た目だけの修正。データ・タブの切り替え自体の挙動は変えない。
