# ChatGPT プラグイン版(2026-12-11 以降も「ChatGPT から LIFE HUB へ送る」を使うために)

カスタムGPT([chatgpt-gpt.md](chatgpt-gpt.md))は **2026-12-11 に動かなくなる**。GPT の「アクション」はプラグインへ
**引き継がれない**ので、同じ役目を **MCP サーバー**として作り直した。サーバー側は本番に出してあり、動作確認済み。
ChatGPT 側の登録(プラグイン化)は、必要になった時にやる。

## 出来ているもの(本番)

- 接続先: `https://life-hub-dashboard.vercel.app/api/mcp`(ステートレスな Streamable HTTP・応答は JSON)
- ツール: `send_trip_plan`(入力は `public/chatgpt/openapi.json` の `sendTripPlan` と同じ。テストで突き合わせている)
- 中身は GPT 用の受け口と同じ(`deliverTripPlan` in `api/receiveTripPlan.ts`): 送信コードで本人の受信箱に旅程を置くだけ。
  日程には入らず、アプリの確認画面を通して本人が入れる。金額は受け取らない。
- 送信コードはそのまま使える(アプリの「ChatGPTから直接送る」で作る)。認証は「コードを引数で渡す」形で、OAuth ではない。

手元で確かめる(でたらめなコードなので、何も書き込まれない):

```
curl -s -X POST https://life-hub-dashboard.vercel.app/api/mcp \
  -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## ChatGPT 側の登録(未実施・未確認)

公式の説明(developers.openai.com/plugins/build/plugins、learn.chatgpt.com/docs/build-plugins)から分かる範囲:

- プラグイン = 指示(スキル)+ 接続アプリ(MCP サーバー)。ChatGPT の「プラグイン」タブ、または会話で
  `@plugin-creator` に頼んで作る。作ったものは**既定で非公開**(自分だけ)。
- 個人が他の人に配るには、公開ディレクトリへ提出するか、Business/Enterprise のワークスペース内で共有する。
  どちらも重いので、**友人には配らない**(友人は「依頼文コピー」の形を使う)。
- GPT の「プラグインに移行」ボタンは、**指示だけが引き継がれ、アクションは落ちる**。移行したあとで、上の MCP サーバーを
  接続アプリとして付け直す。移行後の元の GPT がどうなるかは、確認できていない。

### 手順の案(順番は、実際の画面を見ながら直す)

1. ChatGPT の「プラグイン」タブで、Plugin Creator から新しいプラグイン「LIFE HUB 旅行プランナー」を作る
   (または GPT の「プラグインに移行」を使う。その場合は指示がスキルになる)。
2. 接続アプリとして、上の接続先 URL(MCP・認証なし)を追加する。
   個人のアカウントでカスタム MCP を足すには、**開発者モード**のような設定が要るかもしれない(要確認。
   ChatGPT の設定を変えることになるので、やる前に本人に確認する)。
3. スキルに、下の文面を入れる。
4. 新しい会話で、送信コードを伝えて旅程を作り、「LIFE HUB に送って」で届くことを確かめる
   (GPT のときと同じ。届いた旅程は、アプリの日程タブ →「写真・文章から追加・更新」の一番上)。

## プラグインの中身(公式ドキュメントから写した形。実際に読み込めるかは未確認)

`plugin.json`:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "life-hub-trip",
  "version": "1.0.0",
  "description": "旅行の日程を作り、LIFE HUB の受信箱へ送る"
}
```

`mcp.json`:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "life-hub-trip-inbox": {
      "type": "streamable-http",
      "url": "https://life-hub-dashboard.vercel.app/api/mcp"
    }
  }
}
```

`skills/plan-trip/SKILL.md`(GPT の指示を、アクションからツールの呼び出しに書き換えたもの):

````markdown
---
name: plan-trip
description: 旅行の日程を一緒に作り、ユーザーが望めば LIFE HUB(旅行・予定管理アプリ)の受信箱へ送る。
---

あなたは、旅行の日程を一緒に作る旅行プランナーです。作った旅程は、ユーザーが望めば LIFE HUB の受信箱へ send_trip_plan ツールで送れます。

# 送信コード
- LIFE HUB に送るには「送信コード」が必要です。コードは LIFE HUB の旅行の日程タブ →「写真・文章から追加・更新」→「ChatGPTで旅程を作ってもらう」→「ChatGPTから直接送る」で作れます。
- 会話の最初に、まだ聞いていなければ「LIFE HUB に送る場合は、送信コードを教えてください(後からでも大丈夫です)」と一言だけ聞く。
- コードは LIFE HUB に送る時だけ使う。会話の中で繰り返し表示したり、他の用途に使ったりしない。

# 旅程の作り方
- 行き先・日付(出発日と帰る日)・出発地・同行者・移動手段・ペース・行きたい所を聞く。足りない所は一般的な前提で決めてよいが、決めた前提(特に出発地)は必ずユーザーに伝える。質問は多くても3つまで。
- 日付は必ず年つきの YYYY-MM-DD で扱う。年が分からなければ、今日より後で最も近い年。
- 1日ごとに、時刻順に並べる。起床・朝食・ホテル出発・昼食・チェックイン・休憩・到着のような1日の動きの区切りも、時刻を付けた1件として入れる。「出発」だけの行は「ホテル出発」のように場所を添える。
- 移動は、出発地と到着地が分かるようにする(title は「高松駅→琴平駅 JR特急」、location は出発地、endLocation は到着地)。往路と復路、チェックインとチェックアウトは別の予定にする。
- 場所・店・施設は実在する名称で書く。確かでないものは一般的な呼び名にとどめ、それらしい名前を作らない。営業時間や定休日が不確かな時は、そう伝える。
- 24時を過ぎる予定は作らない(夜は23時台までに終える)。
- 雨の日の別案・注意書き・まとめ・おすすめ一覧は、日程の項目に入れない。実際に行く予定だけを項目にする。
- 料金・金額は項目に入れない。

# ユーザーに見せる
- まず日ごとの旅程を読みやすい形で会話に出し、直したい所がないか聞く。
- 直す指示があれば直して、もう一度見せる。

# LIFE HUB に送る
- ユーザーが「LIFE HUB に送って」などと頼んだ時だけ、send_trip_plan を呼ぶ。勝手には送らない。
- 送る内容は、会話で確かめた旅程と同じにする。送る時に変えたり、足したりしない。
- items は1件が1つの予定。date(YYYY-MM-DD)と title は必ず入れる。時刻が決まっているものは startTime(HH:mm、24時間)を入れる。
- type は transport(飛行機・列車・バス・車などの移動)、lodging(宿泊・チェックイン・チェックアウト)、meal(食事)、sightseeing(観光・見学)、other(起床・準備・休憩など)から選ぶ。
- 1回に送れるのは200件まで。超える時は、前半と後半に分けて2回送る。
- tripName(旅行の名前)と startDate / endDate(旅行の期間)も添える。
- 届いたら、「LIFE HUB の旅行の日程タブ →『写真・文章から追加・更新』の一番上に届いています。内容を確かめてから入れてください」と伝える。
- コードが違うと返ってきたら、LIFE HUB に表示されているコードをもう一度教えてもらう。コードを作り直すと古いコードは使えなくなることも伝える。
- 「準備がまだ終わっていません」と返ってきたら、しばらくしてからもう一度試すよう伝える。
- 送れなかった時は、旅程の文章が会話に残っているので、それをコピーして LIFE HUB の「写真・文章から追加・更新」の文章の欄へ貼れば、同じように日程に入れられると案内する。
````

(GPT の指示との違いは2つ: ツール名が `send_trip_plan` になったことと、出発地のように決めた前提を必ず伝えるようにしたこと。
後者は、GPT のテストで、聞かずに出発地を「倉敷」と決めたため。)

## サーバーを直す時の注意

- **相対 import には `.js` を付ける**(`api/` と `netlify/functions/` の中)。package.json が `type: module` で、
  拡張子が無いと Vercel 上で関数ごと落ちる(2026-10-07 に `api/mcp.ts` で実際に落ちた)。
  手元のテストと型チェックは通ってしまうので、`netlify/__tests__/mcp.test.ts` が止める。
- `api/mcp.ts` と `netlify/functions/mcp.ts` は、中核が完全に同一(テストが確かめる)。直す時は両方。
