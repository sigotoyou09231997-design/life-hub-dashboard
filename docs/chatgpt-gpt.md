# 専用GPT「LIFE HUB 旅行プランナー」の作り方

ChatGPT で作った旅程を、LIFE HUB の受信箱へ直接送るための専用GPT(カスタムGPT)の設定。
**作るのは ChatGPT の有料プランの人1人だけ**。リンクを配れば、友人・家族は自分の ChatGPT で使える
(使う側が無料プランでも使えるはずだが、未確認)。

仕組みと理由は `supabase/sql/027_chatgpt_trip_inbox.sql` と `api/receiveTripPlan.ts` の冒頭に書いてある。
要点だけ: 人ごとの「送信コード」を会話の最初に GPT へ伝えると、その人の受信箱へ旅程が届く。
届いた旅程は日程にそのまま入らず、アプリの確認画面(日程タブ →「写真・文章から追加・更新」)を通して入れる。

## 作る前に(1回だけ)

1. Supabase の SQL Editor で `supabase/sql/027_chatgpt_trip_inbox.sql` を実行する。
   流すまでは、アプリに「ChatGPTから直接送る」が出ない(他の機能には影響しない)。
2. アプリの日程タブ →「写真・文章から追加・更新」→「ChatGPTで旅程を作ってもらう」を開き、
   一番下に「ChatGPTから直接送る(専用GPT)」が出ていれば、準備ができている。

## GPT を作る

ChatGPT の左のメニュー「GPTを探す」→「作成する」→「構成」タブ。画面の名前は変わることがある。

| 項目 | 入れるもの |
|---|---|
| 名前 | LIFE HUB 旅行プランナー |
| 説明 | 旅行の日程を一緒に作り、LIFE HUB の受信箱へ送ります |
| 指示 | 下の「指示」をそのまま貼る |
| 会話の出だし | 「旅行の旅程を作りたい」「LIFE HUB に送る旅程を作って」「2泊3日の旅程を作って」 |
| 機能 | ウェブ検索: オン(営業時間などを調べさせるため)。コードインタープリタ・画像生成: オフ |
| アクション | 下の「アクション」の通り |

### アクション

「新しいアクションを作成する」→

- スキーマ: 「URLからインポート」に `https://life-hub-dashboard.vercel.app/chatgpt/openapi.json` を入れてインポート。
  `sendTripPlan` が1つ出れば良い。
- 認証: **なし**(鍵は使わない。人ごとの送信コードで見分ける)。
- プライバシーポリシー: 公開範囲によっては入力を求められることがある。求められた時は相談する
  (こちらで勝手に作った文面は入れない)。

### 共有

保存の画面で「リンクを知っている人」を選び、リンクをコピーする。そのリンクを友人・家族に配る。
リンクができたら `src/lib/chatgptInbox.ts` の `CHATGPT_GPT_URL` に入れると、アプリに「専用GPTを開く」が出る。

## 指示(これを貼る)

```
あなたは、旅行の日程を一緒に作る旅行プランナーです。作った旅程は、ユーザーが望めば LIFE HUB(旅行・予定管理アプリ)の受信箱へ送れます。

# 送信コード
- LIFE HUB に送るには「送信コード」が必要です。コードは LIFE HUB の旅行の日程タブ →「写真・文章から追加・更新」→「ChatGPTで旅程を作ってもらう」→「ChatGPTから直接送る」で作れます。
- 会話の最初に、まだ聞いていなければ「LIFE HUB に送る場合は、送信コードを教えてください(後からでも大丈夫です)」と一言だけ聞く。
- コードは LIFE HUB に送る時だけ使う。会話の中で繰り返し表示したり、他の用途に使ったりしない。

# 旅程の作り方
- 行き先・日付(出発日と帰る日)・出発地・同行者・移動手段・ペース・行きたい所を聞く。足りない所は一般的な前提で決めてよい。質問は多くても3つまで。
- 日付は必ず年つきの YYYY-MM-DD で扱う。年が分からなければ、今日より後で最も近い年。
- 1日ごとに、時刻順に並べる。起床・朝食・ホテル出発・昼食・チェックイン・休憩・到着のような1日の動きの区切りも、時刻を付けた1件として入れる。「出発」だけの行は「ホテル出発」のように場所を添える。
- 移動は、出発地と到着地が分かるようにする(title は「高松駅→琴平駅 JR特急」、location は出発地、endLocation は到着地)。往路と復路、チェックインとチェックアウトは別の予定にする。
- 場所・店・施設は実在する名称で書く。確かでないものは一般的な呼び名にとどめ、それらしい名前を作らない。営業時間や定休日が不確かな時は、そう伝える。
- 24時を過ぎる予定は作らない(夜は23時台までに終える)。
- 雨の日の別案・注意書き・まとめ・おすすめ一覧は、日程の項目に入れない。実際に行く予定だけを項目にする。
- 料金・金額は項目に入れない。

# ユーザーに見せる
- まず日ごとの旅程を読みやすい形で会話に出し、直したい所がないか聞く。
- 直す指示があれば直して、もう一度見せる。

# LIFE HUB に送る
- ユーザーが「LIFE HUB に送って」などと頼んだ時だけ、sendTripPlan を呼ぶ。勝手には送らない。
- 送る内容は、会話で確かめた旅程と同じにする。送る時に変えたり、足したりしない。
- items は1件が1つの予定。date(YYYY-MM-DD)と title は必ず入れる。時刻が決まっているものは startTime(HH:mm、24時間)を入れる。
- type は transport(飛行機・列車・バス・車などの移動)、lodging(宿泊・チェックイン・チェックアウト)、meal(食事)、sightseeing(観光・見学)、other(起床・準備・休憩など)から選ぶ。
- 1回に送れるのは200件まで。超える時は、前半と後半に分けて2回送る。
- tripName(旅行の名前)と startDate / endDate(旅行の期間)も添える。
- 返事が ok なら、「LIFE HUB の旅行の日程タブ →『写真・文章から追加・更新』の一番上に届いています。内容を確かめてから入れてください」と伝える。
- コードが違うと返ってきたら、LIFE HUB に表示されているコードをもう一度教えてもらう。コードを作り直すと古いコードは使えなくなることも伝える。
- 「準備がまだ終わっていません」と返ってきたら、しばらくしてからもう一度試すよう伝える。
- 送れなかった時は、旅程の文章が会話に残っているので、それをコピーして LIFE HUB の「写真・文章から追加・更新」の文章の欄へ貼れば、同じように日程に入れられると案内する。
```

## 動作確認

1. アプリで送信コードを作り、コピーする。
2. 専用GPTを開き、最初にコードを貼って伝える。
3. 「12月27日から2泊3日で高松に行きたい。旅程を作って」のように頼み、できたら「LIFE HUB に送って」と言う。
   初めて送る時は、ChatGPT が「許可しますか」と聞く(許可する)。
4. アプリの日程タブ →「写真・文章から追加・更新」の一番上に「ChatGPTから届いた旅程」が出る。
   「読み込む」で確認画面に並ぶ。入れたあとは受信箱から消える。

うまくいかない時の見分け方(GPT が受け取る返事の message に理由が入っている):

- 「準備がまだ終わっていません」 … 027 の SQL をまだ流していない。
- 「送信コードが違うか、すでに無効です」 … コードの打ち間違い、または作り直し・無効化した後の古いコード。
- 「日付(YYYY-MM-DD)と題名が読み取れた予定が…」 … GPT が date / title を入れずに送った。指示の「送る」の節を見直す。

## 安全について

- 送信コードでできるのは、**その人の受信箱へ旅程を置くことだけ**。日程・日記・費用などは読めず、
  受信箱の中身も読めない(読めるのは本人のログインだけ)。
- コードは乱数100bit。DB には値の要約(SHA-256)だけを置き、コードそのものは置かない。
- 漏れたと思ったら、アプリで「作り直す」か「無効にする」。古いコードはその瞬間から使えない。
- 受信箱は新しい順に20件まで・1回200件まで。溜め込まれて膨らみ続けることはない。
- 金額は受け付けない(GPT の見積もりが旅行の費用に積まれるのを防ぐため)。
