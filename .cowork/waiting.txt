旅行のしおりを共有.md — Supabase のスキーマ変更が必要なため保留（2026-08-30）。

  なぜ実装できないのか:
    「ログインしていない人がリンクを開くだけで見られる」を成り立たせるには、旅行のデータが
    その人のブラウザから読める場所に無いといけない。いまの旅行データ（trips / tripSchedule /
    tripExpenses / tripPackingItems / tripRoutePlaces / diaryEntries）は、端末内の IndexedDB と、
    同期先の Supabase のテーブルにしかない。同期先のテーブルは RLS で「自分の user_id の行だけ」に
    絞られているので、他人はログインしても読めない。
    共有リンクを成り立たせるには supabase/sql/ に次のような追加が要る:
      - 共有の合鍵を持つテーブル（旅行id・公開用トークン・公開/非公開の別）
      - そのトークンを持つ匿名アクセスにだけ、その旅行に紐づく行の読み取りを許す RLS ポリシー
        （上の6テーブルぶん）
    SQL は人が本番で実行する必要があるため、依頼のルールどおりここで止まる。

  進めるなら、聞きたいこと:
    1. 公開範囲は「リンクを知っている人は誰でも見られる」でよいか
       （合鍵付きURLなので、URLが人手に渡ると誰でも見られる）。
    2. 日記も共有に含めるか。日程・費用・持ち物・ルートと違い、日記は書いた場所の
       緯度経度まで持っている（src/types/index.ts の DiaryEntry）。既定では外す方が安全だと思う。
    3. 費用（誰がいくら使ったか）を含めるか。
    4. 共有をやめたときは、そのリンクを無効にしてよいか。

  条件が決まれば、こちらで用意できるもの:
    - supabase/sql/020_trip_shares.sql（本人が本番で実行する）
    - 旅行詳細に「共有する／やめる」の切り替え（初期状態は依頼のとおり「共有しない」）
    - 共有リンク用の閲覧専用ページ（ログイン不要、編集なし）
